## 总体评价

本周的主要进步是技术回答的骨架更加稳定。面对“先确认、成功后再执行、失败时恢复”“一个模块计算、另一个模块只显示”等题目时，大多数回答都能保留主要处理方向。对资源替换、对象回收、引用清理、输入状态和动画中断等工程场景，也已经能够写出具有实际操作意义的流程，而不是只翻译孤立名词。

当前最需要提高的是精确度。第一类问题是把相近概念替换成了不同含义的词，例如把采样数写成采样频率、运动矢量写成移动方向、物理质量写成品质、曝光值写成亮度。第二类问题是复杂题目虽然写出了主干，却漏掉“只执行一次”“任意一项失败”“仍然有效”“完成清理后”“不得写回”等限制。第三类问题是面试题有自己的技术想法，但没有逐项回应题目指定的说明框架。

语言层面仍需集中修正 `〜する時に` 的泛用、助词缺失、从句主语错误以及片假名拼写。你已经能用日语组织较长的技术说明，下一阶段不必一味增加长度，而应优先保证每个名词、条件和动作都与中文题意一一对应。

## 本周标注重点

### 1. 条件、顺序与成功时机

- [[2026-08-24#2026-08-24#练习 1|8/24-1 终结技资源扣除]]：应明确技能组件先验证状态与资源，只有成功进入施放状态后才扣除资源。
- [[2026-08-24#2026-08-24#练习 9|8/24-9 AI 重新选择目标]]：清除旧引用后，还要保留“确认仍有有效候选”这一独立步骤。
- [[2026-08-24#2026-08-25#练习 10|8/25-10 检查点写入]]：临时保存、内容验证、替换成功和更新时间的先后顺序表达稳定。
- [[2026-08-24#2026-08-26#练习 6|8/26-6 行动队列取消]]：句子没有写完，导致“被取消的命令不能改变角色状态”这一重要限制缺失。
- [[2026-08-24#2026-08-27#练习 6|8/27-6 装备预设验证]]：`いずれか一つでも` 才能准确表达“任意一项失败”，不能写成全部失败。
- [[2026-08-24#2026-08-28#练习 6|8/28-6 制作材料预留]]：预留、成功后消耗、失败后解除的三段流程完整，是较好的条件题结构。
- [[2026-08-24#2026-08-29#练习 4|8/29-4 配置表重新读取]]：应先解析并验证全部新数据，成功后才替换旧缓存并通知使用方。
- [[2026-08-24#2026-08-30#练习 1|8/30-1 推进任务阶段]]：`成功した後で` 应直接连接后续动作，突出状态更新成功是追加历史记录的前提。

归纳：写流程题时，先在草稿中标出“前置确认、允许条件、执行动作、失败处理、成功后动作”。推荐使用 `〜ことを確認してから`、`〜に成功した場合のみ`、`〜した後で` 和 `一つでも〜なら`。

### 2. 职责主体与数据边界

- [[2026-08-24#2026-08-24#练习 2|8/24-2 伤害数值与 UI]]：计算模块生成最终数值，UI 只决定显示形式和动画，职责划分已经表达清楚。
- [[2026-08-24#2026-08-24#练习 5|8/24-5 Gameplay Tag 失败提示]]：提示模块只接收失败原因，不应重新判断角色状态。
- [[2026-08-24#2026-08-25#练习 4|8/25-4 相机模式栈]]：应使用 `キャラクターコントローラーだけが変更できます` 明确唯一修改者。
- [[2026-08-24#2026-08-26#练习 1|8/26-1 交互失败提示]]：条件不满足时，只把失败原因交给 UI；`だけ` 不能省略。
- [[2026-08-24#2026-08-27#练习 2|8/27-2 小地图数据边界]]：游戏逻辑只提供世界坐标和图标类型，UI 负责转换、限制和显示，完成度较高。
- [[2026-08-24#2026-08-27#练习 5|8/27-5 材质定义与运行时实例]]：共享定义与运行时实例的边界表达完整，应继续保持这种显式主语结构。
- [[2026-08-24#2026-08-28#练习 1|8/28-1 锁定目标评分]]：评分模块只计算候选分数，角色控制器确认可见性后再应用结果。
- [[2026-08-24#2026-08-30#练习 10|8/30-10 进度条补间]]：显示层可以生成中间显示值，但不能将其写回逻辑数据；`補間途中の表示値` 是关键限定。

归纳：职责题尽量让每个分句都出现明确主语，并使用 `〜のみを担当します`、`〜だけを受け取ります`、`〜してはいけません` 写清能力边界和禁止事项。

- [[2026-08-24#2026-08-24#练习 3|8/24-3 World Partition 卡顿]]：被加载单元数不能替换成笼统的对象数，观测对象必须保持精确。
- [[2026-08-24#2026-08-25#练习 13|8/25-13 大量 Tick 优化]]：技术想法有价值，但没有依次回答测量、停用、降频、集中更新和优化后验证。
- [[2026-08-24#2026-08-26#练习 12|8/26-12 Unity GC 峰值]]：分配量、主要对象类型和分配堆栈位置必须全部保留。
- [[2026-08-24#2026-08-27#练习 3|8/27-3 Nanite GPU 开销]]：使用 `可視インスタンス数`、`マテリアルの複雑さ`、`オクルージョン前後の描画時間` 更准确。
- [[2026-08-24#2026-08-28#练习 13|8/28-13 计时器管理器]]：时间轮方案具体，但还需补充按 ID 取消的方法，以及同一帧集中到期的压力测试。
- [[2026-08-24#2026-08-29#练习 13|8/29-13 调试记录系统]]：事件编号、时间戳和关联 ID 的用途说明较好；还可补充固定容量、分类开关和采样。
- [[2026-08-24#2026-08-30#练习 3|8/30-3 光线追踪阴影闪烁]]：`サンプル数`、`履歴の重み`、`モーションベクトル` 是三个不同概念，不能用近义词代替。

归纳：面试题先复述题目要求的项目，再逐项回答。调试题至少包含“记录什么、在什么时机记录、与什么比较、用什么结果判断”的完整闭环。

### 4. 生命周期、引用与失败收尾

- [[2026-08-24#2026-08-24#练习 6|8/24-6 对象工厂失败清理]]：初始化失败后，应把原因返回请求方，并销毁已经生成的临时对象。
- [[2026-08-24#2026-08-25#练习 11|8/25-11 Niagara 对象池]]：返回对象池前应重置用户参数、解除父子关系并停止残留发射。
- [[2026-08-24#2026-08-26#练习 4|8/26-4 事件观察者销毁]]：观察者解除订阅后，还要确认事件发布者没有保留旧引用。
- [[2026-08-24#2026-08-27#练习 4|8/27-4 出生点登记]]：关卡卸载前既要注销，也要清除管理器中的引用，两个动作不能合并。
- [[2026-08-24#2026-08-28#练习 5|8/28-5 跳过过场动画]]：停止序列、恢复相机、销毁仅为该过场创建的对象，限定范围要完整保留。
- [[2026-08-24#2026-08-28#练习 10|8/28-10 跨关卡弱引用]]：`レベルのアンロードをまたいで` 保存引用时，应在每次访问前确认对象仍有效。
- [[2026-08-24#2026-08-29#练习 5|8/29-5 Render Target 替换]]：先创建新资源，成功后切换引用，最后释放旧资源，顺序准确。
- [[2026-08-24#2026-08-30#练习 4|8/30-4 遍历期间延迟销毁]]：遍历时只记录销毁请求，结束后统一处理，避免立即修改集合。

归纳：生命周期题固定检查“谁拥有、何时取消、何时解除引用、何时释放、失败后保留什么”。资源替换时优先使用“新资源验证成功后再切换引用”的安全结构。

### 5. 动画与物理术语要保持概念精度

- [[2026-08-24#2026-08-24#练习 7|8/24-7 Motion Warping]]：目标点失效后应取消 `位置補正`，并让动画 `自然に終了する`。
- [[2026-08-24#2026-08-25#练习 8|8/25-8 移动平台抖动]]：应比较平台速度、地面检测结果和更新顺序，不能只写笼统的振动现象。
- [[2026-08-24#2026-08-26#练习 7|8/26-7 分层骨骼混合]]：使用 `レイヤードボーンブレンド`、`駆動する` 和 `ボーンマスク`。
- [[2026-08-24#2026-08-27#练习 7|8/27-7 Root Motion 阻挡]]：反馈实际移动距离后，还要明确丢弃未完成的 `残りの移動量`。
- [[2026-08-24#2026-08-28#练习 8|8/28-8 物理抓取清理]]：物体被销毁与主动销毁物体含义不同；物理约束应使用 `制約`。
- [[2026-08-24#2026-08-29#练习 7|8/29-7 Distance Matching]]：动画曲线中的剩余距离应说 `アニメーションカーブ上の残り距離`。
- [[2026-08-24#2026-08-30#练习 7|8/30-7 骨骼 LOD 与姿势缓存]]：切换后应使旧 `ポーズキャッシュ` 无效，并基于新的 `ボーンセット` 重新计算姿势。
- [[2026-08-24#2026-08-30#练习 8|8/30-8 击退与冲量]]：物理质量是 `質量`，不是 `品質`；冲量宜说 `力積（インパルス）`。

归纳：技术术语不能只凭中文汉字选择日语汉字。遇到渲染、动画和物理概念时，先确认它代表“数量、频率、方向、矢量、质量、品质、冲量还是持续力”，再选择对应词。

### 6. 高频语言问题

1. **`〜する時に` 使用过多**：一般条件优先使用 `〜するときは`；已经发生的条件使用 `〜したときは`；强调完成后的动作使用 `〜した後で`。
2. **从句主语的助词不稳定**：注意 `対象が有効か`、`キャラクターが移動した距離`、`条件が満たされていない`，不要被中文语序带成 `は` 或错误的被动态。
3. **名词之间缺少连接**：常见问题包括 `マテリアルの組み合わせ`、`アニメーションカーブ上の距離`、`該当フレームの割り当て量`。
4. **片假名拼写和长音**：反复出现 `モージュル`、`オディオ`、`マネジャー`、`キャラッシュ`、`バンディングボックス` 等错误。写完后应单独检查片假名。
5. **相近词误用**：区分 `実装／実現`、`仕様／規格`、`補間／補完`、`質量／品質`、`露出値／輝度`、`サンプル数／サンプリング周波数`。
6. **句子没有完整结束**：较长回答偶尔停在 `〜し、` 或缺少最终谓语。提交前从句尾倒着检查每个分句是否闭合。

### 7. 日常口语与职场沟通

- [[2026-08-24#2026-08-24#练习 14|8/24-14 借伞]]：注意 `忘れたことに気づいた`、`天気予報によると` 和表达意愿的 `借りようと思う`。
- [[2026-08-24#2026-08-24#练习 15|8/24-15 测试受阻汇报]]：开发中的“实现”是 `実装`；规格问题、处理方针和完成预期应分别写清。
- [[2026-08-24#2026-08-25#练习 14|8/25-14 图书续借]]：已借的书用 `借りた本`，到期日用 `返却期限`，请求续借应保持礼貌语体。
- [[2026-08-24#2026-08-26#练习 15|8/26-15 提前离开与交接]]：提前下班使用 `早退`，并用 `共有します` 表达把注意事项交接给同事。
- [[2026-08-24#2026-08-27#练习 15|8/27-15 方案确认期限]]：`二つの案とそれぞれのリスク`、`明日の正午まで` 必须准确保留数量和期限。
- [[2026-08-24#2026-08-28#练习 14|8/28-14 咖啡店多收费]]：礼貌请求应用 `確認していただけますか`，不能只用陈述式 `確認していただきます`。
- [[2026-08-24#2026-08-29#练习 15|8/29-15 验收条件确认]]：`受け入れ条件が明確になっていません` 表示当前状态，请负责人确认时使用 `確認していただきたいです`。

归纳：日常口语继续保持自然普通体；职场表达固定使用“背景／现状 → 已完成事项 → 剩余问题 → 希望对方采取的动作 → 期限”。请求句必须表现为请求或希望，不能写成单纯的未来陈述。

## 面试口语评判标准

下周继续使用五项自检，每项 0～2 分，共 10 分：

1. **题意覆盖**：题目列出的项目是否逐项回应，没有用相近概念替换。
2. **条件完整**：前提、成功时机、失败分支、次数和禁止事项是否保留。
3. **职责明确**：是否说明哪个模块负责计算、保存、应用、通知或显示。
4. **验证具体**：是否包含记录项、采样时机、比较对象和判定标准。
5. **日语准确**：助词、从句、术语、片假名拼写和语体是否自然。

建议回答前先把题目拆成三至五个关键词，回答后逐个划掉。面试题即使有更好的扩展方案，也应先完整回应指定项目，再补充自己的设计。
