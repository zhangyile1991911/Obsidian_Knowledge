# 2026-06-15 一周总结

> [!info] 本周概况
> 本总结覆盖 2026-06-15 至 2026-06-21。主周文件完成 70 道每日中译日练习，另参考了 6/19、6/20、6/21 的技术专项练习和代码设计模式表达。整体主题集中在 Unity / Unreal gameplay 工程语境：渲染、资源管理、状态机、输入缓冲、UI 与 Gameplay 解耦、存档迁移、性能分析和调试表达。

## 整体评价

本周的技术表达已经能覆盖核心意思，尤其是资源释放、状态机、UI 接口、输入缓存、性能分析等 gameplay 工程话题。主要问题不在于句子完全无法成立，而在于三个层面还不稳定：

1. 技术术语容易按中文或英文直译，导致词不达意。
2. 动作对象、时序和条件关系偶尔偏移。
3. 请求句和技术说明的语气还不够统一，常在普通形、请求形和说明形之间摇摆。

最值得优先复习的是“术语块 + 句型块”一起记。例如不要只记 `Addressables`，还要记 `動的にロードしたAddressablesリソースを解放する`；不要只记 `入力バッファ`，还要记 `入力をバッファリングし、操作可能になった後すぐに実行する`。

## 高频问题

### 1. 技术术语需要更贴近引擎语境

本周出现多次“能理解，但不像实际项目里会说的日语”的表达。尤其是 Unity / Unreal 语境差异、外来语拼写、以及中文术语直译。

| 不稳定表达 | 更自然表达 | 说明 |
| --- | --- | --- |
| 過剰なドローコール | オーバードロー / 過剰描画 | “过度绘制”不是 draw call 过多 |
| カストーシャド | カスケードシャドウ | 外来语拼写错误 |
| スキル決算 / ダメージ決算 | ダメージ計算 / 判定処理 | `決算` 是财务结算 |
| アドレスリソース | Addressablesリソース | Unity Addressables 固定说法 |
| コライダー | コリジョン / 当たり判定 | Unreal 攻击判定语境更自然 |
| 遷移 | 移行 | 存档迁移是 `セーブデータの移行` |
| プーリング | ポーリング | polling 和 pooling 要分清 |
| シリアライズ | デシリアライズ | 读取旧存档时是反序列化 |

### 2. 动作对象经常需要重新确认

有些句子保留了关键词，但动作施加对象偏了。例如“UI 不直接改状态”不是“通过 UI 按钮处理状态”，而是“UI 通过 Gameplay 层接口请求状态切换”；“释放资源前确认引用”不是确认资源依赖场景，而是确认动画或音效没有引用目标资源。

复习时建议先拆中文：

- 谁执行动作
- 对什么对象执行动作
- 什么条件下执行
- 执行之后达到什么状态

代表例题：[[2026-06-19 技術日本語練習#^tech-0619-controller-layer|6/19 技術 コントローラー層]]、[[2026-06-19 技術日本語練習#^tech-0619-resource-release|6/19 技術 対象リソース]]、[[2026-06-20 技術日本語練習#^tech-0620-gameplay-interface|6/20 技術 Gameplay層]]、[[2026-06-21 技術日本語練習#^tech-0621-ui-hp-interface|6/21 技術 ダメージ処理]]

### 3. 条件、顺序和持续时间表达要更精确

本周经常混淆 `まで`、`までに`、`前に`、`後に`、`してから`。这类错误会直接改变逻辑。

| 中文 | 推荐句型 |
| --- | --- |
| 直到动画结束前都不要进入 | `アニメーションが終了するまで〜しない` |
| 完成后再恢复 | `完了してから再開する` |
| 收到快照后再恢复 | `受け取ってから再開する` |
| 写入完成前不要刷新 | `書き込み完了前に〜しない` |
| 硬直结束前输入 | `硬直終了前に入力した場合は` |

代表例题：[[2026-06-15#2026-06-19#练习 2|6/19-2 受け取ってから]]、[[2026-06-20 技術日本語練習#^tech-0620-hit-reaction|6/20 技術 終了するまで]]、[[2026-06-21 技術日本語練習#^tech-0621-stun-state|6/21 技術 再遷移しない]]、[[2026-06-19 技術日本語練習#^tech-0619-async-save|6/19 技術 書き込み完了前]]

### 5. 资源管理与性能分析表达明显增多

资源管理题里要区分 `解放する`、`アンロードする`、`回収される`、`参照が残る`。性能题里要区分原因、现象和优化动作。

常用句块：

- `参照が残っていると、メモリが回収されなくなる可能性があります`
- `動的にロードしたAddressablesリソースを解放する`
- `一時オブジェクトが大量に生成されている`
- `文字列連結や一時的なListの生成を減らす`
- `CPU負荷のスパイクが発生している`
- `メインスレッドの処理時間を大きく占めている`
