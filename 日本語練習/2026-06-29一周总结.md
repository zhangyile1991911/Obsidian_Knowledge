# 2026-06-29 一周总结

> [!info] 本周概况
> 本总结覆盖 2026-06-29 至 2026-07-05。主周文件 [[2026-06-29]] 完成 70 道每日中译日练习；专项练习包括 [[2026-06-29 技術日本語練習]] 和 [[UE5 技術面接シミュレーション：Q&Aまとめ]]。整体主题从上一周的 UI / Gameplay 分层、资源生命周期、Profiler 说明和卡牌 Ability 设计，进一步扩展到 UE5 第三人称射击、Weapon Ability 设计、Projectile Damage Snapshot、Anim Notify 结束路径，以及逻辑处理和演出处理分离。

## 整体评价

本周最大的进步是：很多句子已经能先覆盖题目核心意思，再补充技术对象和处理关系。特别是 Profiler 结果说明、UI 局部刷新、状态机限制、存档字段迁移、卡牌效果对象的数据持有边界，整体比上周更稳定。

仍然需要集中修正的问题主要有三类：

1. 外来语和技术术语拼写还会反复出错，例如 `フォマット`、`フォーワード`、`オブサーバー`、`ボロック`、`OnDestory`、`スロート`。
2. “分离、切り分け、解耦、只做某事”的句型还不够稳定，容易少掉 `〜だけにし`、`そうすることで`、`別々に処理する` 这类连接。
3. 面试型回答已经能说结论，但还需要更稳定地补出“理由、风险、收益、替代处理”，尤其是 Weapon Ability、Projectile、Anim Notify 和ロジック/演出分離。

## 高频问题

### 1. 外来语拼写要继续专项复习

本周最明显的重复问题是外来语拼写。每日练习里出现了 `フォマット` 应为 `フォーマット`，专项复习里出现 `ボロック` 应为 `ブロック`、`オブサーバー` 应为 `オブザーバー`、`フォーワード` 应为 `フォワード`。这些词如果在面试中拼错，技术内容虽然能懂，但会明显削弱专业感。

### 2. UI 局部刷新和重建避免的表达更稳定了

UI 相关题集中训练了“只更新发生变化的部分，不重建整个 UI”。你能比较稳定地写出 `〜だけを更新し、〜全体を再生成しないようにしてください`。需要继续注意的是，`UIパネルを再開する` 不如 `再度開く`，`枠` 和 `スロット` 的语义差别也要根据题目对象选择。

### 3. 状态机、输入限制和动画结束时序仍需打磨

状态机类题已经多次覆盖：攻击硬直、翻滚结束、受击反应、落地恢复、普通攻击输入、冲刺状态。主要问题不是不知道技术逻辑，而是日语中“结束前一直不允许”的表达需要固定成 `〜が終了するまでは、〜へ遷移すべきではありません` 或 `〜を無効化し続けるべきです`。

### 5. Profiler 结果说明要从“看到了”变成“原因和影响”

Profiler 相关题已经覆盖主线程耗时、Shader Variant、动画曲线、技能冷却文本、Buff 层数文本、GC Allocation。当前最好用的句型是 `Profilerの結果を見ると、〜が原因で、〜が発生していることが分かりました` 或 `〜がメインスレッドの処理時間を大きく占めています`。下周可以继续把 Profiler 和具体优化动作绑定起来。

### 6. 存档字段迁移的动词选择还要稳定

存档题反复出现“补齐、创建、映射、转换、替换”。你已经能抓住字段处理方向，但动词有时会偏离，例如 `追加する` 不等于创建新结构，`換算する` 不等于字段转换，`破棄された` 不如 `廃止された` 或 `削除された`。建议固定整理成 `補完する`、`作成する`、`マッピングする`、`変換する`、`置き換える`。

关联例题：[[2026-06-29#2026-06-29#练习 6|6/29-6 デフォルト値で補完]]、[[2026-06-29#2026-07-02#练习 6|7/2-6 列挙値にマッピング]]、[[2026-06-29#2026-07-04#练习 6|7/4-6 経験値フィールドに変換]]、[[2026-06-29#2026-07-05#练习 6|7/5-6 戦闘設定フィールドに置き換える]]

### 7. 卡牌 Ability 和“状态不持有”表达继续强化

卡牌 Ability 相关题从“效果定义共享”发展到“工厂只保存生成规则”“效果对象只保存定义”“临时护盾值放到战斗状态”。这个方向很好，因为它和面试中的架构解释直接相关。下周可以继续练 `状態を保持しない`、`効果定義だけを保持する`、`戦闘状態で管理する`、`一時的な値をAbility側に持たせない`。
