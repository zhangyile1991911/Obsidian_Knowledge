# 2026-08-10 一周总结

> [!info] 本周练习概况
> 本周完成了 7 天、共 105 道中译日练习，题型保持为每天 13 道 Gameplay 工程技术题、1 道日常对话、1 道职场表达。原始练习见 [[2026-08-10]]。

## 总体评价

本周最大的进步，是已经能够用日语完整说明较复杂的工程逻辑。状态管理、UI 与数据分层、资源生命周期、性能分析、动画与物理调试等题目，基本都能准确传达技术意图。尤其在“先确认什么、再执行什么”“由哪个系统负责判断”“用什么证据定位问题”这三类表达上，回答已经具有技术交流和面试说明所需的基本结构。

目前影响自然度的主要问题不是技术理解，而是日语组织方式：容易沿用中文的复合名词和语序，省略必要的「の」「を」「が」，把动作执行者写成被判断的对象，或只罗列操作而没有明确先后、条件和结果。另外，「〜する時に」使用偏多；说明通用规则时，多数情况下「〜するときは」更自然。

## 本周标注重点

### 1. 用明确的顺序说明 Gameplay 流程

复杂逻辑不能只把多个动词并列起来，需要显式说明处理顺序、分支条件和最终结果。

- [[2026-08-10#2026-08-10#练习 6|8/10-6 Boss 阶段切换]]：先停止当前行为，再播放过渡演出，最后切换到下一阶段。重点表达是 <mark>決まった順序で</mark>。
- [[2026-08-10#2026-08-14#练习 6|8/14-6 装备强化]]：结果应表达为 <mark>成功または失敗</mark>，并分别说明成功和失败时的后续处理。
- [[2026-08-10#2026-08-14#练习 13|8/14-13 道具使用]]：适合使用「まず〜を確認し、使用可能であれば〜してから〜する」组织条件与顺序。
- [[2026-08-10#2026-08-16#练习 8|8/16-8 伤害计算]]：固定减伤、比例抗性、护盾应按顺序处理，关键词是 <mark>ダメージ軽減</mark> 和 <mark>割合耐性</mark>。
- [[2026-08-10#2026-08-16#练习 13|8/16-13 连招验证]]：验证结果可表述为 <mark>安定して動作している</mark>，复现条件则是 <mark>固定された入力シーケンス</mark>。

推荐固定句型：

> まず〜を確認し、条件を満たしている場合は〜します。その後、〜を更新します。

### 2. 明确“谁判断、谁保存、谁显示”

本周多次涉及 Gameplay、数据层与 UI 的职责划分。日语中必须让主语和责任对象清楚，避免出现“判定本身进行判断”或“UI 决定游戏结果”这样的表达。

- [[2026-08-10#2026-08-10#练习 10|8/10-10 任务面板]]：UI 应 <mark>クエストデータの変化を監視し、その変更を受けて</mark> 表示を更新する。
- [[2026-08-10#2026-08-10#练习 11|8/10-11 伤害与 UI]]：<mark>HPの減少処理</mark> 由 Gameplay 侧负责，UI 只负责显示结果。
- [[2026-08-10#2026-08-11#练习 8|8/11-8 背包问题排查]]：先确认 <mark>セルの占有状態</mark>，再确认物品实例，最后确认 UI；可概括为 <mark>三つの手順</mark>。
- [[2026-08-10#2026-08-12#练习 2|8/12-2 伤害数字]]：表现层只接收已经确定的伤害结果，不应重新计算伤害。
- [[2026-08-10#2026-08-13#练习 4|8/13-4 背包同步]]：先保证数据正确，再刷新界面，而不是让 UI 反过来修正数据。
- [[2026-08-10#2026-08-14#练习 2|8/14-2 UI 输入事件]]：输入由控制器处理，再向 UI 发出事件，更容易保持职责边界。
- [[2026-08-10#2026-08-14#练习 11|8/14-11 奖励逻辑]]：奖励计算应能 <mark>単体で</mark> 测试，不依赖界面是否存在。

推荐固定句型：

> 〜の判定は Gameplay 側で行い、UI はその結果を受け取って表示だけを更新します。

### 3. 调试说明要包含“现象、证据、确认点”

本周的调试题已经能提出正确方向，但有时表达停留在“查看一下”。更专业的说法应明确记录什么、比较什么，以及如何据此判断原因。

- [[2026-08-10#2026-08-10#练习 9|8/10-9 AI 感知与寻路]]：分别记录 <mark>感知の更新タイミング</mark> 和路径状态，避免把两个系统的问题混在一起。
- [[2026-08-10#2026-08-13#练习 3|8/13-3 AI 警戒]]：记录玩家进入 <mark>感知範囲</mark> 的时间点，再与警戒状态变化进行对照。
- [[2026-08-10#2026-08-13#练习 11|8/13-11 渲染调试]]：CPU、GPU 与内存要分别测量，才能定位 <mark>主な負荷要因</mark>。
- [[2026-08-10#2026-08-14#练习 4|8/14-4 命中判定]]：同时记录攻击帧和 <mark>判定が発生するタイミング</mark>，确认二者是否一致。
- [[2026-08-10#2026-08-16#练习 11|8/16-11 GC 峰值]]：不仅要找出分配量，还要定位对象被生成的 <mark>箇所</mark>。
- [[2026-08-10#2026-08-16#练习 10|8/16-10 摄像机碰撞]]：平滑插值的目标是让距离 <mark>突然跳ねない</mark>。

推荐固定句型：

> 〜のタイミングと〜の状態をログに記録し、両者が一致しているか確認します。

### 4. 动画、物理和表现类词汇更加具体

这类题目中的技术判断大多正确，但直译词容易降低自然度。应优先使用业界常见名词和搭配。

- [[2026-08-10#2026-08-10#练习 3|8/10-3 转身动画]]：Root Motion、输入方向和状态切换需要分别确认。
- [[2026-08-10#2026-08-11#练习 13|8/11-13 新手引导]]：引导表现可说 <mark>ガイド表示</mark>，不宜机械直译为不常见的复合词。
- [[2026-08-10#2026-08-12#练习 8|8/12-8 AI 巡逻]]：目标点使用 <mark>ウェイポイント</mark>。
- [[2026-08-10#2026-08-15#练习 4|8/15-4 动画混合]]：瞄准姿势只在 <mark>上半身で</mark> 混合，下半身继续使用移动动画。
- [[2026-08-10#2026-08-15#练习 7|8/15-7 遮挡剔除]]：边界框应使用 <mark>バウンディングボックス</mark>。
- [[2026-08-10#2026-08-15#练习 8|8/15-8 移动平台]]：角色出现抖动可说 <mark>ガタつく</mark>，并检查更新顺序和 <mark>アタッチ方法</mark>。
- [[2026-08-10#2026-08-16#练习 3|8/16-3 Motion Warping]]：需要区分目标点、Root Motion 与校正方向。
- [[2026-08-10#2026-08-16#练习 6|8/16-6 Hit Stop]]：直接使用 <mark>ヒットストップ</mark>，同时说明它不应影响 UI 的时间更新。

### 5. 资源、存档和生命周期表达

本周已经形成了较好的生命周期意识：创建、缓存、复用、释放、解绑和迁移需要成对考虑。下一步是把这种设计思路说得更简洁、自然。

- [[2026-08-10#2026-08-10#练习 12|8/10-12 旧存档兼容]]：读取旧版本时补充默认值，并保持版本迁移逻辑集中管理。
- [[2026-08-10#2026-08-11#练习 2|8/11-2 对象池预热]]：区分预热、复用和峰值期间创建新对象造成的卡顿。
- [[2026-08-10#2026-08-12#练习 11|8/12-11 加载界面]]：加载界面负责显示进度，不负责决定资源加载顺序。
- [[2026-08-10#2026-08-13#练习 12|8/13-12 投射物回收]]：放回对象池前应重置速度、特效和命中状态。
- [[2026-08-10#2026-08-15#练习 2|8/15-2 Addressables]]：实例销毁后仍要释放对应句柄，避免引用残留。
- [[2026-08-10#2026-08-15#练习 10|8/15-10 存档写入]]：先写入临时文件，校验成功后再替换正式存档。
- [[2026-08-10#2026-08-16#练习 9|8/16-9 硬引用链]]：检查资源是否因为间接硬引用而被提前加载。
- [[2026-08-10#2026-08-16#练习 12|8/16-12 事件解绑]]：对象销毁前先解绑事件，避免之后继续收到回调。

### 6. 性能优化要说明“成本来自哪里”

回答性能题时，不要只说“进行优化”，而要指出 CPU、GPU、内存或分配压力的来源，以及采用该措施后减少了什么。

- [[2026-08-10#2026-08-11#练习 7|8/11-7 UI 性能]]：关注层级、刷新频率和 <mark>透明度の重なり</mark>。
- [[2026-08-10#2026-08-12#练习 6|8/12-6 小地图刷新]]：只有玩家移动或地图状态变化时才更新。
- [[2026-08-10#2026-08-13#练习 6|8/13-6 粒子质量]]：按平台切换质量等级，并限制同屏粒子数量。
- [[2026-08-10#2026-08-15#练习 9|8/15-9 音频并发]]：限制 <mark>同時再生数</mark>，设置优先级，避免重要 <mark>効果音が埋もれない</mark>。
- [[2026-08-10#2026-08-15#练习 11|8/15-11 本地化 UI]]：根据文本长度调整布局，保证文字 <mark>はみ出さない</mark>。
- [[2026-08-10#2026-08-16#练习 4|8/16-4 长列表 UI]]：使用虚拟化，只创建当前可见范围内的条目。
- [[2026-08-10#2026-08-16#练习 5|8/16-5 Shader Variant]]：根据构建目标剔除未使用变体，降低包体和加载成本。
- [[2026-08-10#2026-08-16#练习 7|8/16-7 批量寻路]]：将大量请求分散到多个帧处理，避免单帧尖峰。

### 7. 本周高频语言问题

#### 「〜する時に」与「〜するときは」

说明普遍适用的操作规则时，优先使用「〜するときは」。例如：

> セーブデータを読み込むときは、最初にバージョンを確認します。

#### 补足必要的助词

中文可以连续堆叠名词，日语通常需要用「の」明确关系。

- キャラクター状態 → キャラクターの状態
- バトル演出時間制御 → バトル演出の時間制御
- 更新タイミング確認 → 更新のタイミングを確認する

#### 区分自动词、他动词和可能表达

- 「状態が更新した」→「状態が更新された」
- 「処理を続けるか」若强调能力或条件，应为「処理を続けられるか」
- 「安定に動く」→「安定して動く」

#### 避免中文式技术词

- 到着可能性 → 到達可能性
- バレ程度 → 露出度
- 並行数 → 同時再生数
- 固定減少 → 固定値のダメージ軽減
- 抵抗パーセント → 割合耐性
- 実行順番 → 更新順序／実行順序
- くっつける方式 → アタッチ方法
- バンディング → バインディング

[[2026-08-10#2026-08-15#练习 5|8/15-5 掩体评分]] 中的「可达性、暴露度」应自然表达为「到達可能性・露出度に基づいて」。[[2026-08-10#2026-08-15#练习 13|8/15-13 武器属性]] 中可使用 <mark>最終ステータス</mark> 和 <mark>各段階の計算結果</mark> 来说明最终值及各阶段结果。

### 8. 日常与职场表达

日常和职场题整体完成度较高，语气基本自然。剩余问题主要是遗漏助词、时间表达过于直译，以及动词搭配不够准确。

- [[2026-08-10#2026-08-15#练习 14|8/15-14 忘带耳机]]：「イヤホンを家に忘れた」比「落ちた」准确。
- [[2026-08-10#2026-08-16#练习 14|8/16-14 下雨改天]]：自然会话中可以使用「雨が強くなってきたから、また今度にしよう」。
- [[2026-08-10#2026-08-16#练习 15|8/16-15 需求理解偏差]]：先「認識が合っているか確認したうえで」，再共享「修正案」。
- 职场中“补充测试结果”宜说「テスト結果を追記する」，“发布日期”宜说「リリース日」。

## 面试口语评判标准

下周进行技术口语或面试式表达时，可以按以下顺序自检：

1. **结论是否先出现**：先说明采用什么设计或先检查什么。
2. **责任主体是否清楚**：谁判断、谁保存、谁显示、谁释放。
3. **顺序与条件是否完整**：使用「まず」「その後」「〜した場合」「〜してから」。
4. **调试证据是否具体**：说明要记录的时间点、状态、数值和比较对象。
5. **术语是否自然**：优先使用常见技术词，避免逐字拼接中文复合名词。
6. **句子能否在两到三句内说完**：先保证结构清楚，再补充细节。

## 下周练习安排

继续保持每天 15 题、13/1/1 的构成，并重点强化以下内容：

1. **责任边界**：Gameplay、数据层、UI、输入层之间的职责说明。
2. **顺序与分支**：技能消耗、装备强化、伤害结算、存档迁移等多阶段流程。
3. **证据型调试**：用日志、Profiler、时间点和状态对照说明排查方法。
4. **生命周期**：资源句柄、事件解绑、对象池复用、临时文件和硬引用链。
5. **性能表达**：GC 分配、列表虚拟化、Shader Variant、分帧处理和音频并发。
6. **动画与物理**：Motion Warping、Root Motion、Hit Stop、摄像机碰撞和平滑插值。
7. **自然职场表达**：需求确认、修正方案、风险说明、进度汇报和请求协作。

题目应继续避免只考术语翻译，而要要求完整表达“条件—处理—结果”。面试式长题每天最多 5 题，其余题目保持能在一至三句内回答。

## 下周固定表达

1. 〜するときは、まず〜を確認します。
2. 〜に基づいて判断します。
3. 〜の責務として一元的に管理します。
4. 〜してから、〜を更新します。
5. 条件を満たしている場合にのみ〜します。
6. 〜を複数のフレームに分けて処理します。
7. 〜のタイミングと〜の状態が一致しているか確認します。
8. 〜が残らないように、明示的に解放します。
9. UI は〜に直接依存するべきではありません。
10. 〜の部分だけを単体でテストできます。
11. 破棄後もイベントを受け取り続ける可能性があります。
12. 認識が合っているか確認したうえで、修正案を共有します。
