# 2026-06-22 一周总结

> [!info] 本周概况
> 本总结覆盖 2026-06-22 至 2026-06-28。主周文件 [[2026-06-22]] 完成 70 道每日中译日练习；专项练习还包括 [[2026-06-22 技術日本語練習]]、[[UI設計について模擬面接]] 和 [[カード回合制ゲーム：模擬面接まとめ]]。整体主题集中在 Unity / Unreal gameplay 工程表达、UI 架构说明、资源与性能优化、状态机、输入缓冲、存档兼容，以及卡牌回合制战斗系统的面试回答。

## 整体评价

本周的表达已经能覆盖大多数题目的核心意思，尤其是 UI 与 Gameplay 分层、对象池、存档默认值补齐、状态机拆分、卡牌效果封装等技术主题。主要不足不是“完全表达不出来”，而是以下三类问题反复出现：

1. 技术术语拼写或固定搭配不稳定，例如 `オーバードロー`、`パーティクル`、`ステートマシン`、`デフォルト`、`Profiler上では`。
2. 中文逻辑直译成日语后，助词、连接方式和主语关系不自然，例如 `〜による`、`〜が〜する`、`〜だけ、〜する`。
3. 面试回答中可以讲出技术方案，但还需要更稳定地补充“为什么这样设计”和“这样设计带来的收益”。

## 高频问题

### 1. 术语拼写和外来语要继续稳定

本周最常见的问题仍然是外来语拼写和游戏开发固定说法。比如 `オーバードロ` 应为 `オーバードロー`，`パティークル` 应为 `パーティクル`，`ステトーマシン` 应为 `ステートマシン`，`ディフォルト` 应为 `デフォルト`，`プレイや` 应为 `プレイヤー`。这些问题会让句子虽然能懂，但不像正式技术沟通。

代表例题：[[2026-06-22#2026-06-22#练习 1|6/22-1 オーバードロー / パーティクル]]、[[2026-06-22#2026-06-25#练习 2|6/25-2 ステートマシン]]、[[2026-06-22 技術日本語練習#5. Save Data / 版本兼容|技术 Save Data / デフォルト]]、[[2026-06-22 技術日本語練習#7. Cutscene / 跳过演出|技术 Cutscene / Timeline]]

### 2. “原因、条件、结果”的连接方式还要专项练

你已经能把题目的技术要素写出来，但原因句和条件句经常受中文影响。例如 `生成されるによって`、`倒れたによる`、`参照が残るによる` 这类表达需要固定改成 `〜ことで`、`〜によって`、`〜と`、`〜ため`。调试、性能、内存、存档题里这类连接尤其重要。

代表例题：[[2026-06-22#2026-06-22#练习 7|6/22-7 GCスパイク]]、[[2026-06-22#2026-06-25#练习 5|6/25-5 リスト並べ替え]]、[[2026-06-22 技術日本語練習#9. NavMesh / 动态障碍物|技术 NavMesh / 倒れて]]、[[カード回合制ゲーム：模擬面接まとめ#1. Buffシステム：付与タイミング|卡牌 Buff 付与タイミング]]

### 3. UI 和 Gameplay 的职责分离表达明显进步

本周 UI 相关练习很多，整体方向很好：UI 只发送请求或接收通知，实际状态切换和 Gameplay 逻辑放在 Gameplay 层处理。需要继续巩固的固定句型是 `UI側では〜だけを行い、Gameplay層で〜する`、`Gameplay層ではイベント通知だけを行い、UI側が〜を更新する`。

代表例题：[[2026-06-22#2026-06-28#练习 3|6/28-3 UIボタンとGameplay層]]、[[2026-06-22#2026-06-26#练习 3|6/26-3 スキルボタン]]、[[2026-06-22 技術日本語練習#06-23|技术 6/23 Observer Pattern]]、[[カード回合制ゲーム：模擬面接まとめ#5. Observer Pattern：Gameplay層からUI通知|卡牌 Observer Pattern]]
